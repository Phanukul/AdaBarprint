1.1 เทียบให้เห็นชัด: ระบบตอนนี้ VS ระบบ Auto-Print ที่ต้องปรับเพิ่ม

หัวข้อ ระบบ AdaBarprint ปัจจุบัน (Manual) จุดต้องปรับเพิ่มเพื่อให้ Auto-Print ตี 4 ทำงานได้จริง
1. การดึงข้อมูลใหม่ เปิดอ่านไฟล์ db/AdaAccD.db อย่างเดียว ไม่มีตัวดึง API เพิ่มโมดูล sync_master.rs ให้ยิงตรง API2PSMaster V6 (เฉพาะ ~12 ตารางที่ใช้พิมพ์ป้าย) พร้อม Retry ถ้าเน็ตหลุด
2. การประกอบข้อมูลเป็นไฟล์ส่งพิมพ์ ต้องเปิดหน้าจอเว็บ (React DOM) ดึงแม่แบบ+ข้อมูลมาแคปภาพหน้าจอส่งพิมพ์ — ถ้าปิดแท็บ/ติด Lock Screen ตอนตี 4 จะส่งพิมพ์ไม่ได้ เพิ่มตัวสร้างไฟล์พิมพ์ฝั่งหลังบ้าน (Headless Print Renderer ใน Rust) ดึงแม่แบบที่ User ออกแบบไว้ใน TCNMLabelTmpl มาสวมราคาใหม่ → แปลงเป็น PNG/ZPL โดยตรงไม่ต้องเปิด UI
3. การอ่านโปรโมชัน V6 คิวรีจากตาราง POS5 เก่า (TCNTPdtPmtHD) แต่ API2PSMaster V6 ส่งลงตาราง TCNTPmtHD แก้ตัวอ่านโปรโมชันให้อ่านจากตาราง V6 (TCNTPmtHD/GrpDT/Cond) ได้ด้วย ไม่อย่างนั้นซิงค์ V6 แล้วป้ายโปรฯ ไม่ออก
4. การคัดเลือกสินค้า ดึงทีละ max 500 ตัว ไม่มีระบบเช็กตัวที่เปลี่ยนอัตโนมัติ และไม่มีเช็กโปรฯ หมดอายุ สร้างตัวคัดกรอง 4 เคสเปลี่ยนวันนี้ (ปลดเพดาน 500) + เก็บ Hash กันพิมพ์ซ้ำทั้งร้านหากรีสตาร์ต
5. การรันตลอด 24/7 เป็นแอปเปิด-ปิดมือ และเปิด SQLite โหมด Delete อาจชน Lock ถ้ารันพร้อม Sync เพิ่ม Background Service รันอัตโนมัติเมื่อเปิดเครื่อง, เปิด SQLite WAL Mode, ป้องกัน Sleep/Printer หลับ และหมุน Log กันดิสก์เต็ม

1.2 ขอบเขตงาน (ตกลงกับ PM เพื่อกันงานบานปลาย)

In-Scope (ทำในเฟสนี้)

  • ทำทั้งหมดใน AdaBarprint ตัวเดียว ยิงตรง API2PSMaster V6
  • ใช้ db/AdaAccD.db ไฟล์เดียว (เปิด WAL Mode เก็บทั้งข้อมูล Sync + ตารางป้าย + ตารางตั้งเวลา)
  • รองรับเครื่องเปิด 24/7 (Pre-Sync กระจายเวลา + Auto-Print + Auto-Recover หลังไฟดับ/Reboot)
  • User ตั้งเวลา/กติกา/ถาด/Dry-Run เองผ่านหน้าจอ UI (และ Admin ตั้ง URL/Key ในแท็บขั้นสูง ไม่ต้องแก้ไฟล์ .env)

Out-of-Scope (ไม่ทำในเฟสนี้)

  • ไม่แก้ระบบ AdaPos6.0StoreFront, ada-gateway, หรือ Backend API2PSMaster
  • ไม่ดึงตารางขาย/สต็อก/CRM ของ POS (ดึงเฉพาะ 10–12 ตารางสินค้า ราคา โปรโมชัน และสาขา)
  • ยังไม่ทำแจ้งเตือนส่งออก LINE OA / SMS / Email (ดูผลบน Dashboard + Cover Sheet แทน)
  • ยังไม่รวมป้ายราคาดิจิทัล E-Ink (ESL)

2.1 แผนภาพที่ 1: ภาพรวมระบบทั้งหมด (Big Picture Architecture)

สรุปภาพนี้ใน 5 วิ: ซ้ายคือหน้าจอตั้งค่าและดูผลของร้าน • กลางคือตัวทำงานอัตโนมัติตอนตี 4 (ทำงานแม้ไม่เปิดจอ) • ขวาคือดึงข้อมูลส่วนกลางลง DB เดียวแล้วพิมพ์แยกถาดให้พนักงานตอนเช้า
แผนภาพที่ 1: ภาพรวม 4 เสาหลักเรียงซ้ายไปขวา (ตั้งค่า → ส่วนกลาง/DB เดียว → ระบบตี 4 → เครื่องพิมพ์/เปิดร้าน)

2.2 แผนภาพที่ 2: การดึงข้อมูลจาก API2PSMaster V6 (ไม่ต้องใช้ RabbitMQ / Gateway)

ข้อเท็จจริงจากการตรวจโค้ด POS6: การดึงข้อมูล Master (สินค้า/ราคา/โปรโมชัน) ลง AdaAccD.db ใช้ HTTP REST API ของ API2PSMaster V6 เท่านั้น ไม่ได้ดึงจาก RabbitMQ (RabbitMQ 13 คิวอยู่ฝั่ง Upload บิลขายเท่านั้น) ดังนั้น AdaBarprint จึงยิง HTTP ตรงหา API2PSMaster เองได้เลยเฉพาะ ~12 ตารางที่เกี่ยวกับป้าย
สรุปภาพนี้ใน 5 วิ: อ่านจากซ้ายไปขวา: ดึงเฉพาะข้อมูลสินค้า/ราคา/โปรฯ ใหม่ล่าสุดจากส่วนกลาง → เซฟลง AdaAccD.db (ไม่ทับแบบป้ายของร้าน) → จดเวลาซิงค์ไว้รอรอบพรุ่งนี้
แผนภาพที่ 2: ขั้นตอนซิงค์ข้อมูลตรง 5 ก้าว (Server HQ → โหลดเพิ่มเฉพาะที่แก้ → เซฟปลอดภัย → DB เดียว → จดเวลา)

2.3 แผนภาพที่ 3: เส้นเวลาทำงานตี 4 บนเครื่องที่เปิดตลอด 24/7 (Pre-Sync + Final Check + Print)

สรุปภาพนี้ใน 5 วิ: ทยอยดูดข้อมูลล่วงหน้า 03:15–03:45 (กันสาขาแย่ง Server) → 04:00 เช็กซ้ำ → 04:02 คัดตัวที่เปลี่ยน → 04:04 ทำไฟล์ → 04:06 ปลุก Printer พิมพ์รอเปิดร้าน
แผนภาพที่ 3: เส้นเวลาตั้งแต่ Pre-Sync ตอนตี 3 ถึงพนักงานเปิดร้านตอนเช้า (24/7 Mode)

2.4 แผนภาพที่ 4: Flowchart ตัดสินใจครบวงจร (มีจุดตัดสินใจ ใช่/ไม่ และกรณี Error)

สรุปภาพนี้ใน 5 วิ: เดินเส้นตรงจากบนลงล่างคือ "ทางปกติจนพิมพ์เสร็จ" • ถ้าติดขัดหรือซ้ำ ระบบจะดีดออกทางขวาทั้งหมด
แผนภาพที่ 4: Flowchart แนวตั้ง 6 ด่าน (เดินตรงลงล่างคือทางสำเร็จ • แยกออกขวาคือกรณีข้าม/หยุด/กู้คืน)

2.6 แผนภาพที่ 5: Cross-Functional Swimlane Diagram (แสดงว่าแต่ละส่วนทำหน้าที่อะไรในแต่ละช่วงเวลา)

สรุปภาพนี้ใน 5 วิ: อ่านจากซ้ายไปขวาตามลำดับเลข ① → ⑨ (เลขเรียงตามเวลาจริง) จะเห็นชัดทันทีว่าแต่ละฝ่ายส่งต่องานให้กันตอนกี่โมง
แผนภาพที่ 5 (Swimlane Diagram): อ่านตามลำดับ ① → ⑨ แยกหน้าที่ชัดเจนทั้ง 5 ส่วน

2.7 การเก็บ Log และกู้คืนเมื่อพิมพ์ค้างกลางคัน (ตัวอย่าง: มี 20 รายการ พิมพ์ได้ 5 แล้วเครื่องพิมพ์ Lost)

1. พิมพ์แล้ว (1–5) ✅
ระบบส่งทีละหน้า/ดวง: ใบ 1–5 ถูกจดว่า PRINTED และอัปเดตประวัติแล้ว (ไม่พิมพ์ซ้ำ)
2. เครื่องดับ (ใบที่ 6) ⛔
หยุดพิมพ์ทันที! ยกเลิกคิวค้างใน Windows Spooler ทิ้งเพื่อป้องกันพิมพ์เบิ้ล
3. เก็บคิวค้าง (6–20) 📝
จด Run = PARTIAL และคิว 6–20 = FAILED รออยู่ในฐานข้อมูลพร้อมรหัส Error
4. ตอนเปิดร้าน / กลับมาติด 🔁
เลือกให้พิมพ์ต่ออัตโนมัติ (AUTO_RESUME) หรือรอคนกดปุ่ม [Reprint] / [ส่งเข้า Manual]
สำคัญมาก: ถ้าส่งพิมพ์ 20 รายการเป็น Spooler Job ก้อนใหญ่ก้อนเดียว ระบบจะไม่รู้เลยว่าเครื่องพิมพ์ดับตอนใบที่ 5 ดังนั้น Print Dispatcher ต้องส่งเป็น Chunk/Page ย่อย พร้อมเช็กสถานะเครื่องพิมพ์คั่นทุกรอบ เพื่อให้รู้ชัดเจนว่าใบที่ 1–5 ออกแล้ว และใบที่ 6–20 ยังไม่ออก!

1. สิ่งที่ระบบเก็บ Log ไว้ให้อัตโนมัติตอนตี 4

  • Thermal LAN (IP:9100): ส่งทีละดวงและรอ Ack → ดวงที่ 1–5 ถูกมาร์ก PRINTED, พอถึงดวงที่ 6 เครื่อง Lost ระบบหยุดทันทีแล้วมาร์กดวง 6–20 เป็น FAILED
  • Windows Driver (A4/B5): ส่งพิมพ์ทีละหน้า (หรือ Chunk 1–2 หน้า) แล้วเช็ก PrinterStatus/Spooler Error หลังจบแต่ละหน้า
  • บันทึกลง 3 ตารางใน AdaAccD.db:
    • TCNTLabelSchedRun: สถานะ = PARTIAL, สำเร็จ = 5, ค้าง = 15, รหัส Error = E-PRT-001/002
    • TCNTLabelSchedQueue: แถว 1–5 = PRINTED (บันทึก Watermark แล้ว) | แถว 6–20 = FAILED (คงค้างรอซ่อม)
    • TCNTLabelLog: เก็บ Log เหตุการณ์ (เวลาที่พัง + ชื่อเครื่องพิมพ์ + Error Message)
    • กันพิมพ์เบิ้ลจาก Spooler: เมื่อตัดจบว่า Error ระบบจะ สั่ง Cancel คิวค้างใน Windows Spooler ทิ้งทันที เพื่อไม่ให้ Windows แอบปล่อยของเก่าซ้ำตอนเครื่องกลับมา Online
  • ถ้าเครื่องกลับมาทำงานปกติทีหลัง จะพิมพ์ต่ออัตโนมัติไหม? (ตั้งเลือกได้ 2 แบบใน FTLscOnPrinterBack):
    • 1) ระยะสั้น (ภายใน ~10 นาทีตอนตี 4): Agent ลอง Ping/Poll เครื่องพิมพ์ซ้ำทุก 30–60 วิ หากกลับมาทัน จะพิมพ์ต่อจากใบที่ 6–20 ให้อัตโนมัติทันที
    • 2) ระยะยาว (พ้นช่วง Retry แล้วกลับมา Online ตอน 07:00 น.): เลือกได้ตาม Policy ร้าน — AUTO_RESUME (พิมพ์ต่อเฉพาะ 6–20 ให้อัตโนมัติถ้ายังอยู่ในวันเดียวกันก่อน 09:00 น.) หรือ WAIT_CONFIRM (ค่าเริ่มต้นที่ปลอดภัยสุด: รอให้พนักงานกดปุ่ม Reprint / Manual เองกันพิมพ์ชนตอนตั้งถาด)

2. ทางเลือกให้ User จัดการตอนเช้า (กด Auto หรือโหลดไปพิมพ์ Manual เอง)

  • หน้าแรกจะขึ้นแถบแจ้งเตือน "รอบ 04:00 น. พิมพ์สำเร็จ 5 / ค้างพิมพ์ 15 รายการ (E-PRT-002)"
  • วิธีที่ 1 — กดพิมพ์ซ้ำอัตโนมัติ (1 คลิก): กดปุ่ม [Reprint Failed Only (15)] ระบบพิมพ์เฉพาะแถว 6–20 ที่สถานะ FAILED ออกเครื่องพิมพ์เดิมทันที (1–5 ไม่พิมพ์ซ้ำ)
  • วิธีที่ 2 — ส่งเข้าหน้าจอพิมพ์ Manual ให้ User กดเอง: กดปุ่ม [ส่ง 15 รายการที่ค้างไปหน้าพิมพ์ Manual] (load-to-manual) ระบบจะดึงเฉพาะแถว 6–20 เข้าตารางหน้าหลักของ AdaBarprint เพื่อเปลี่ยนเครื่องพิมพ์สำรอง ปรับจำนวน หรือเลือกกดพิมพ์เองทีละตัวแบบ Manual ได้ 100%
  • วิธีตรวจสอบย้อนหลังว่า "อะไรพิมพ์ไปแล้ว": เปิดดูจากหน้าประวัติ (TCNTLabelSchedQueue กรอง FTLsqStatus='PRINTED' หรือหน้า History จาก TCNTLabelJobDt โดยดู FTLjbSource='2') ส่วนตัวโปรแกรมเองจะเช็กจาก TCNTLabelSchedWatermark ก่อนพิมพ์รอบถัดไปเสมอ
